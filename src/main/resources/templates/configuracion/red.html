Importante: Test-NetConnection desde esta PC no prueba el celular; solo confirma que Windows puede llegar a su propio puerto.

  • HTTP 8081 no abre: revise firewall, puertos Docker o aislamiento WiFi/Ethernet.
  • HTTP 8081 abre pero HTTPS 8443 no: reinicie Docker para cargar el certificado HTTPS nuevo y acepte la advertencia del navegador.
  • HTTPS 8443 abre: el celular ya llega al sistema; luego debe aparecer como ultimo acceso detectado.

En Windows PowerShell pruebe el puerto HTTPS:

Test-NetConnection 192.168.18.10 -Port 8443

Y pruebe el puerto HTTP auxiliar:

Test-NetConnection 192.168.18.10 -Port 8081

Para revisar si la regla existe:

netsh advfirewall firewall show rule name="Sistema Libreria Movil"

Si falta la regla, abra CMD o PowerShell como administrador y ejecute:

netsh advfirewall firewall add rule name="Sistema Libreria Movil" dir=in action=allow protocol=TCP localport=8443,8081 profile=any

En Docker confirme que los puertos publicados incluyan 0.0.0.0:8443 y 0.0.0.0:8081:

docker ps --format "table {{.Names}}\t{{.Ports}}"

Si actualizó tambien el docker-compose.yml, recree el contenedor de la app:

docker compose up -d --force-recreate app

Escanee el QR principal o el QR de prueba. Si esta sección no cambia, la solicitud no está llegando al sistema: revise firewall de Windows, red invitada o aislamiento entre WiFi y Ethernet del router.

Configuración de IP

La IP se detecta automáticamente la primera vez que se instala el sistema. Use "Detectar IP" si cambió de red, o escriba la IP manualmente si la detección no es correcta. En Docker Desktop para Windows, la IP correcta suele ser la IPv4 de Windows, no 192.168.65.x.
